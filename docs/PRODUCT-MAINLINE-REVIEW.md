# 主线产品优化 · 实施诊断（2026-11-22）

目标链：收藏 → 整理 → 找回 → 阅读 → 复用。不引入新架构、不移除授权、不要求 AI 才能使用。

| 优先级 | 代码证据与真实痛点 | 实施与验收 |
|---|---|---|
| P0 | AddBookmarkModal 只粗略补 https；db.createBookmark 会静默恢复回收站记录，IPC 当新建并重新富化，缺少明确恢复决策 | 清晰 URL 校验/规范预览，明确多链接走已有批量导入；回收站重复项明确定位与恢复，不覆盖原笔记 |

| P0 | ListToolbar 筛选折叠且无完整条件摘要；BookmarkPanel 零结果与空库同文案；smart 查询忽略部分显式筛选 | 可关闭筛选标签、清除全部与全库搜索；空态说明范围；筛选变化清空旧多选，避免误操作隐藏项 |

## 实际补测后发现并修复

- 真实135M小模型输出了仅1条候选却引用[2]/[3]的文本：增加引用范围校验；不展示该段生成，返回明确关键词结果。该校验并非语义事实核验，不声称解决所有幻觉。
- 后台抓取/AI回来时可能覆盖用户刚改的标题/描述：按当前记录与原自动内容决策，不覆盖人工更改。
- 删除等待/处理中的收藏再恢复会停在处理中：移入回收站将未结束状态置为跳过；排队任务不再对回收站开始处理。保留完成状态与原笔记。
- 扩展鉴权探活已改成recent接口，但弹窗仍读取不存在版本导致vundefined；修复为真实鉴权状态，保留401原因，提交/批量提交增加10s超时。补原扩展JS到真实HTTP桥接/SQLite测试；浏览器存储仅为测试替身，扩展GUI仍需父会话验收。

- 标签计数原SQL COUNT了关联表（含已回收项），现改为只计当前非回收记录，与标签筛选一致，补真实增删恢复回归。
