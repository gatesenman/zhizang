# 智藏内容区独立审查（只读代码审查，未运行界面）

范围：用户标红的主内容区；不扩产品功能。仅新增本文件；未修改组件/CSS、依赖或构建，未操作 Windows/GUI。截图事实由父代理提供；以下尺寸为建议验收目标，不是已测结果。并行实现期间代码可能变化，行号仅供定位。

## 5 项优先改进及明确验收标准

### 1. 标题、范围和工具栏收成一个有层级的工作区头（P0）
- 定位：`ListToolbar.tsx:143–181`，`App.tsx:299–347`，`styles.css:703–707,739`。
- 现状：知识库眉题、星标标题、泛化副标题、独立扩大搜索按钮、操作行各占一层；顶部已有新增，下方零结果时再放新增/批量粘贴。`total===0` 是当前查询结果为零，并不代表整个知识库为空。工具行不换行，却有多个 small 控件。
- 建议：内容头第一行只留“当前目录标题 + 结果数量”，第二行统一排序、筛选、多选；取消无助于决策的知识库眉题/通用口号。搜索范围与已有搜索条件合并为一个上下文区域，不再成为独立大按钮行。顶部新增保留全局主入口；空态按语境给单一引导（见第 3 项），不要在工具栏额外叠一组新增/粘贴。
- 验收：1024×645、无条件/未多选时，从列表面板顶边到第一条内容或空态容器顶边 ≤120px；只有一个 h1；计数紧邻标题；无条件时无空筛选占位行；工具按钮高 ≥28px；任意宽度不出现叠字、互相遮挡或水平页面滚动。不要只用 CSS 隐藏功能造成不可达。

### 2. 未选中不分半屏；选中后给阅读足够空间（P0）
- 定位：`App.tsx:371–381` 无条件挂载预览，`WebPreview.tsx` 未选空态，`styles.css:703,709,729` 的固定/最小宽度。
- 现状：截图红框里约 422px 列表 + 426px 空预览；没有选中时两块空态竞争注意力。源码宽度规则与截图不完全相同，不能直接以截图推断当前实际像素。
- 建议：无有效 selected 时列表占满主区，不保留地球占位半屏；选中才展开预览，提供明确“关闭详情”入口，关闭不删除收藏、不清除筛选。在窄窗口确保阅读宽度，而不是机械五五分。
- 验收目标（允许 ±16px 的视觉误差，但不允许最小宽度溢出）：1024×645 左导航 168–190px，选中时列表 320–360px，预览至少 450px；1280×800 导航 190–218px、列表 380–420px、预览剩余且 ≥600px；1440×900 导航 200–218px、列表 420–460px、预览剩余且 ≥740px。未选时三档列表均填满剩余宽度；列表和正文独立垂直滚动。关闭预览后焦点回到原收藏，滚动位置不跳顶。

### 3. 空态只给与当前上下文匹配的一步，不重复“全部搜索”（P0）
- 定位：`BookmarkPanel.tsx:235–255`，`ListToolbar.tsx:147–158`。
- 现状：范围扩大在标题区域和列表空态同时出现；星标为空时却引导“新增”，新建未必进入星标。错误、加载、真正为空目前有分支，需保留，不能美化成同一空白面板。
- 建议：真正全部为空→“添加首条收藏”；星标/分类为空→明确当前范围为空并给“查看全部收藏”；有筛选零结果→保留条件，主动作“清除条件”，扩大范围为次动作；收件箱整理完/空回收站用各自完成态，不制造故障感。扩大范围只保留一个同义入口，保留关键词且显式显示范围已变化。
- 验收：星标 0 条时无“数据已丢失”暗示，也不承诺新增后自动星标；同一屏“在全部收藏中搜索/到全部收藏查找”合计 ≤1 处；筛选零结果可一次点击清除条件；网络/数据库加载失败显示错误与重试而不是零条完成态；重试期间不清空查询。空态文案最多两行主体说明、最多一个主按钮和一个次按钮。

### 4. 多选是稳定的上下文模式，不是把工作区标题全替换（P1）
- 定位：`ListToolbar.tsx:95–139` 提前 return，`BookmarkPanel.tsx:279–307,352–374`，`styles.css` 批量浮条/复选框规则。
- 现状：选中一条后整个标题与范围消失；移动、标签、星标、已读、重新分析、删除全挤进批量条。当前页全选有明确文案，应保留。
- 建议：标题/目录/数量与筛选条件不消失，仅工具动作行切换为“已选 N 项 + 移动/标签 + 更多 + 取消”；删除放危险分区，重新分析降为更多；勾选态 picked 与正在预览 selected 视觉区分。空列表禁用全选。补齐复选框可访问名称、取消选择按钮名称。
- 验收：从 0→1→全选当前页→取消，标题基线、列表首项 y 坐标不跳（≤4px）；1024 下动作可换行或收纳但不裁切，取消始终可见；移动/删除只影响明确选中的当前页项目，分页/切换范围不遗留不可见选择；点击复选框不触发打开/访问；Tab 可找到每个复选框，Space 只切换勾选，屏幕阅读器可读出收藏标题及已勾选状态；回收站仅出现恢复/永久删除对应动作。

### 5. 详情头限高，笔记/阅读/错误保持可达，并做暗色和键盘收口（P1）
- 定位：`WebPreview.tsx:149–218,235–289`，`NoteEditor.tsx:13–17`，`BookmarkPanel.tsx:368–389`，`styles.css:726,740–746`。
- 现状：详情一行标题旁有大量按钮；其下常驻笔记、全部标签。长标签和 6 行笔记可吃光 645px 高度。阅读初次抓取时 `readerLoading` 的界面只位于 `reader` 真值分支，不能保证第一次点击立即展示加载反馈。已有全局 focus-visible，不应误报为没有焦点样式；但 hover 动作及图标按钮仍需逐个核验名称/可达性。
- 建议：标题独占可阅读宽度，主操作只保留阅读/外部打开，编辑、归档、重新分析等进更多；标签默认最多两行并可展开；笔记提供明确折叠/展开与保存状态（不得卸载丢草稿），头部可滚动或限高，为正文保留空间。首次读取立即有加载态并阻止重复提交；错误重试按钮组允许换行。使用既有主题变量替代新增硬编码浅色。
- 验收：1024×645、30 个长标签、100 字标题、6 行笔记时仍有至少 200px 正文可视高度（折叠策略可接受），所有被收起标签/动作可访问；无横向溢出。读文加载首次点击 100ms 内见忙碌反馈，失败后可重试/外部打开，笔记不受影响。保存中/已保存/失败状态均有文字，不只靠颜色；切换收藏后不串写。明暗色普通文字对比 ≥4.5:1、按钮边界/焦点 ≥3:1；Tab 能到更多/阅读/笔记/关闭预览，焦点始终可见；快捷键在笔记输入时不误触全局操作。

## 最终回归清单（待实现者/验收代理执行；本审查未声称通过）

尺寸矩阵：1024×645（用户截图基线）、1280×800、1440×900；每档至少浅色/暗色，列表/卡片两种视图。建议以同一组测试数据逐项截图并记实测尺寸。

| 场景 | 三档窗口均要核验的通过条件 |
|---|---|
| 全部空库 | 一个上下文空态；一个首条收藏引导；无空详情半屏；无筛选空白占位；全选不可用 |
| 星标/分类/收件箱/回收站空 | 文案匹配范围；星标不假装整个库为空；收件箱完成态；回收站无错误新增引导；扩大范围入口不重复 |
| 搜索/筛选零条 | 关键词、范围与条件可见；清除条件和扩大范围可区分；扩大范围不默默丢关键词 |
| 列表有数据但未选 | 主区被列表利用；列表/卡片不被拉成不可读超宽文本；排序/筛选/视图切换可达 |
| 单条选中→关闭→再次选中 | 目标比例、预览最小宽度、正文高度达标；列表位置不变；焦点回位；所见条目/详情一致 |
| 多选 1/多条/全选当前页/取消 | 模式切换不跳动；勾选与预览不同；按钮不挤出；取消可见；分页/换范围无隐形选择；危险动作语义准确 |
| 长标题/URL/标签 | 100 字中文标题、连续 200 字母 URL、30 个 30 字标签；截断可获全文，标签可展开；无挤压/溢出；列表 hover 操作不遮标题；详情正文仍可读 |
| 筛选展开 | 域名、状态、日期范围在 1024 下换行但不出屏；清除后条件芯片同步；长条件不顶掉关闭/排序 |
| 笔记及阅读 | 自动保存、保存失败/重试、切换收藏、折叠展开后草稿保留；首次阅读加载可见；反复点击不重复请求；三种阅读主题可用 |
| 列表/网页/阅读错误 | 保留错误层级与重试；网页错误三按钮换行；重试不清查询/笔记；长错误文本不撑破布局；未把错误渲染成空库 |
| 键盘及暗色 | Tab/Shift+Tab/Enter/Space；复选框、更多、关闭可读名称及焦点；输入笔记时快捷键无冲突；弹层关闭焦点返回；两主题文字/边界/选中与勾选状态对比达标 |

结论：优先实施 1–3，直接对应红框的标题碎片化、重复动作和空详情占半屏；4–5 防止“变漂亮但主线变难用”。以上是建议与验收标准，不是代实现或运行验收报告。
